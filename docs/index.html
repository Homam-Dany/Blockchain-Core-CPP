A Fondation cryptographique

Moteur SHA-256

Implémenté from scratch : compression de blocs de 512 bits, 64 constantes K, sortie de 256 bits. Fonction à sens unique : impossible à inverser.

512 bits / bloc64 × K256 bits

Arbre de Merkle

Hachage hiérarchique récursif par paires des transactions jusqu’à la Merkle Root. Toute altération d’une transaction change la racine : détection immédiate.

H(H1+H2)Merkle Root

Anatomie d’un bloc

Le bloc Genesis (#0) est l’ancre de confiance. Chaque bloc porte :

Index Timestamp PrevHash Merkle Root Nonce Validateur Signature Bloc Hash

# Chaînage cryptographique et audit

Choisissez une attaque ci-dessous, puis cliquez sur un bloc pour le corrompre. L’audit checkIntegrity() repère le premier bloc fautif et isole la rupture :

1. Merkle

Transaction modifiée : racine recalculée ≠ racine stockée.

2. Chaînage

PrevHash ≠ hash du bloc précédent : rupture de chaîne.

3. En-tête

Hash stocké ≠ SHA256(en-tête) : header altéré.

4. Difficulté

Hash sans préfixe cible (ex. 000) : preuve PoW falsifiée.

B Consensus hybride : PoW contre PoS

⛏ Proof of Work (Minage)

  • Minage par force brute : on incrémente le nonce jusqu'au hash cible
  • Cible : hash préfixé par 000 (difficulté réglable)
  • Temps de minage mesuré en millisecondes
Coût de calcul CPUtrès élevé (92%)
Vitesse de validationlente (~460 ms)
Sécurité par le travailforte (inviolable)

◈ Proof of Stake (Validateurs)

  • Sélection pseudo-aléatoire pondérée par la mise (Homam : 50 tokens, Houssam : 30 tokens)
  • Signature cryptographique du bloc avec la clé secrète du validateur
  • Forgeage instantané + récompense de +1 token
Coût de calculquasi nul (< 1%)
Vitesse de validationinstantanée (~0.04 ms)
Sécurité par la miseforte (enjeu financier)

💡 Mesure expérimentale en C++ : 5 blocs en difficulté 4 ➔ ≈ 460 ms en PoW contre ≈ 0,04 ms en PoS.
